# 掘墓的EVE更新助手 1.4.0

开发者：WC飞机杯大王掘墓。参考 XIU2/CloudflareSpeedTest 与 LocalizeLimbusCompany/LLC_BABEL 的方案独立开发，未复制它们的代码。项目来源在主窗口和关于中列出。适用于 Windows 10/11 x64，无需另装 .NET。

## 本次修正

点击「应用并检查」后立即显示进度窗口，先等待管理员权限，然后实时显示节点复核、原设置备份、hosts 写入、DNS 刷新和实际连接检查。进度表示操作阶段，不是剩余时间预测；复核阶段每秒更新，整个过程显示用时。完成或失败继续在同一窗口显示，不再使用原来的完成消息框。应用前仍须完全退出启动器。

测速采用完整文件 GET，避免原先每 16MB 重新请求造成的额外开销。精校准第三轮再比较较大的随机区间。文件提前下载完会继续请求，不能用短样本当成完整持续测速。

每次单连接样本上限为 max(2GiB, (持续秒数+2)×128MiB)，30秒模式约4GiB、60秒约7.75GiB，足够覆盖70MB/s级别的完整测量；达到上限而时长不足仍不推荐。三路对照总上限为对应单连接上限的三倍。

快速和标准主要按通过小请求验证的网络持续速度排序，不再用小请求速率的调和平均值压倒持续速度。小请求测试仍是可用性验证。

## 三档测速

| 档位 | 流程 | 时间 |
| --- | --- | --- |
| 快速 | 所有收集到的 IP 并发 TCP 测4次，按成功率和延迟排序，每域名最多3个候选直接完整 GET；预热2秒后测10秒。三个文件域名轮流测试。 | 约2–3分钟，最多180秒 |
| 标准 | TCP 广筛，多候选短下载初测排序，初筛最多60秒；优胜候选预热2秒后持续测20秒，验证小请求，余时比较更多节点。初测仅供排序，不可直接应用。 | 通常3–5分钟，最多300秒 |
| 精校准 | 三次合并 DNS 轮换结果；所有可连接候选都逐个持续测20秒，不按延迟截断；每域名前3名再各测两轮30秒，比较完整文件与随机区间、小请求。各优胜节点另做两轮三路并行20秒测量。 | 不设总时限，可能数十分钟；可随时停止 |

精校准单连接取三轮中位值，稳定性分数为70%中位值+30%最低一轮；三路对照每轮三条连接等待响应头就绪后共用计时窗口，排除共同2秒预热，按总字节/共同时间计算，两轮均通过才显示保守低值。推荐分数为60%单连接稳定性+40%三路低值；三路对照未齐时保留通过三轮验证的单连接结果，并注明原因。这是选节点的启发式方法，不等于启动器的真实更新吞吐。

精校准需要三轮单连接均通过才选入最终推荐。所有收集到的候选都有首轮完整测试，不代表穷举 CloudFront 全球地址。三个档位均不绑定电信、联通或移动，需在实际目标网络测量。快/标准档到时保留完整结果，未完成结果不能直接应用。

## 网络速度与初代读数

实测 EVE 资源文件返回 Content-Encoding: gzip。初代 CloudflareST v2.2.5 使用的 Go HTTP Transport 默认请求 gzip 并透明解压，下载计数读取解压后的 Body，而且使用滑动估算。新版主列统计收到的压缩文件字节，单位 MiB/s（1MiB=1048576字节）。它不包含 HTTP/TLS 包头开销。

快速档沿用初代完整 GET 与 gzip 读取方式，同时在解压前计数，分别显示「网络单连接」和「解压读取」。后者用于对照初代口径，不代表宽带速度。标准与精校准直接测压缩文件字节，避免额外解压造成 CPU 瓶颈。不能拿解压后的速率直接和压缩下载速率比较。500Mbps理论折合62.5MB/s，运营商实际配置及工具口径仍需实测，不能据此单独判断此前70的来源。

同 IP、同文件的顺序对照：初代工具显示7.04；新版一轮原始字节平均1.01MiB/s；另一次同时计数实测网络2.19MiB/s、解压读取3.86MiB/s。它们发生在不同时间，不能把全部差异归因于解压，也不能认定网络恒定。报告保存在 comparison-1.4.0。数据说明应先统一口径，再比较方法。

## 使用

1. 解压后运行「掘墓的EVE更新助手.exe」。关闭全局代理/TUN后测直连节点。
2. 选择快速、标准或精校准，点击开始测速。列表前3列固定显示域名、TCP延迟、网络单连接速度；其余列可横向滚动。
3. 以前已经找到的高速节点，可通过底部「补充测速节点」填写 `域名 公网IPv4`，每行一个。它只作为本次会话的候选，仍须通过对应域名的 HTTPS 和下载验证，不能直接写入。
4. 完全退出 EVE 游戏和启动器，包括系统托盘，再点击「应用并检查」，允许管理员权限。等待进度窗口完成，重新打开启动器更新。
5. 仍慢时点击检查生效、导出日志，并核对真实启动器下载日志。点击恢复原设置可恢复最近一次应用前的 hosts。

节点来自系统 DNS、阿里/腾讯 DoH、阿里223.5.5.5及223.6.6.6、腾讯119.29.29.29及119.28.28.28的 UDP DNS，并去重合并。某来源失败仍测试其他来源；它们可能返回相同地区的地址。只探测实际解析或用户补充的公网 IPv4，不扫描无关云地址段。

已核实独立处理：resources.eveonline.com（资源）、binaries.eveonline.com（二进制/清单）、launcher.ccpgames.com（当前新版启动器自身更新/安装包）、launcher.eveonline.com（旧版本兼容 JSON，按响应时间选）。前三个文件域名验证齐全才可应用；旧域名可选。TLS SNI、Host和证书校验始终保留真实域名。

读取最新版本和文件清单选择真实文件；清单失败时使用已验证的备用文件，但备用文件仍须实际下载成功。分析本机近期启动器日志中的下载域名和文件路径，查询参数不导出。额外域名只提示，不擅自修改登录和游戏服务器地址。

写 hosts 前复核节点，保存独立备份，保留其他域名、注释、空行与编码。应用后的实际连接检查用正常 DNS 连接，并核对真正远端 IP。恢复时拒绝覆盖后续其他程序的修改。DNS刷新不关闭旧TCP连接，必须重启启动器。本工具不删除 SharedCache、账号或游戏设置。

## 验证范围

73项离线检查涵盖70+MiB/s模拟连接持续30秒且超过旧2GB限制、有限文件重复请求、gzip前后字节分离、共享时窗三路统计、精校准中位数与失败处理、无限预算仍可停止、DNS解析异常、hosts备份与恢复等。

标准档联网实测294.4秒，52个不同IP参加TCP探测、17个候选得到下载初测数据、8个文件节点完成持续验证，三个文件域名和旧版本JSON均有有效推荐。最终快速档结果见独立报告。三路联网测试完成共同20秒计时，收到约300MB文件字节，测得13.93MiB/s。

精校准统计和并行测量通过组件测试；尚未完成所有真实候选的精校准整轮。测试电脑未安装 EVE，也未对电信/联通/移动各地网络做端到端测试。测试未修改系统 hosts。目标电脑上的实际下载、校验、安装和磁盘开销仍需以启动器日志确认。

## 构建

.NET8 SDK：

```powershell
dotnet publish EveUpdateHelper.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=None -p:DebugSymbols=false -o dist
```

内部验证：`--self-test 绝对报告路径`；`--probe-mode 绝对报告路径 Quick|Standard|Precise`；`--probe-one 绝对报告路径 域名 IP 秒数 true|false`；`--probe-parallel 绝对报告路径 域名 IP`；`--diagnose 绝对报告路径`。联网验证不会写hosts；只有用户点击应用或恢复才请求管理员权限。
